# Kirmya Security Operations, Threat Detection, Fraud Prevention & Abuse Protection System

## 1. Overview
The Security Operations, Threat Detection, Fraud Prevention & Abuse Protection System is a core sub-system within Kirmya backend infrastructure (`backend/internal/security`). It provides continuous security monitoring, automated bot and fraud detection, risk scoring, configurable policy rule enforcement, and end-to-end incident/alert lifecycle handling.

---

## 2. Security Event Models & Data Schema

### 2.1 Standard Security Event (`SecurityEvent`)
Represents an auditing log record generated by system actions.
- `id` (UUID): Unique event identifier.
- `user_id` (*UUID): Associated user (optional for unauthenticated attempts).
- `event_type` (string): Standardized event taxonomy (e.g. `login.success`, `login.failure`, `password.changed`, `mfa.enabled`, `brute_force_lockout`).
- `severity` (string): Computed severity level (`Informational`, `Low`, `Medium`, `High`, `Critical`).
- `ip_address` (string): IPv4 or IPv6 client address.
- `user_agent` (string): HTTP User-Agent client browser/device fingerprint.
- `location` (string): Geolocation or IP location metadata.
- `details` (string / JSON): Sanitized execution context details.
- `created_at` (Timestamp): Event generation time.

### 2.2 Enriched Security Event Detail (`SecurityEventDetail`)
Represents extended telemetry for deep threat correlation:
- `correlation_id` (string): Unique trace/correlation identifier (`sec-corr-<uuid>`) for linking events across microservices and log traces.
- `actor_id` (string): ID or IP of the invoking actor.
- `target_entity` (string): Subject entity affected (e.g., `user:123`, `job:456`).
- `risk_level` (string): Risk classification (`Normal`, `Low`, `Medium`, `High`, `Critical`).
- `risk_score` (int): Numerical score from 0 to 100.
- `safe_details` (map[string]any): Sanitized metadata map stripped of sensitive credentials.

## 3. Event Severity Calculation & Sensitive Data Stripping

### 3.1 Severity Calculation Matrix
Severity is calculated dynamically based on threat impact and event classification:
- **Informational**: Standard state queries, login history views, privacy setting checks.
- **Low**: Successful authentication, session listing, API key generation.
- **Medium**: Password changes, MFA enablement/disablement, privacy setting edits.
- **High**: Failed login bursts, brute-force lockouts, suspicious geolocation login attempts, account deletion requests, rapid rate limit violations.
- **Critical**: Bot network detection, mass fake job posting, mass spam messaging, mass application spam, fraud alert triggers.

### 3.2 Sensitive Data Stripping Heuristics
Before storing or logging any event details, payload fields matching sensitive keywords are automatically masked or stripped:
- `password`, `current_password`, `new_password`, `confirm_password`
- `token`, `access_token`, `refresh_token`, `authorization`
- `secret`, `mfa_secret`, `private_key`, `api_key`
- `credit_card`, `card_number`, `cvv`, `ssn`

## 4. Correlation IDs & OpenTelemetry Instrumentation
- Every security operation generates or propagates an HTTP `X-Correlation-ID` header.
- Correlation IDs follow the structure `sec-corr-<timestamp>-<random_hex>`.
- OpenTelemetry tracing spans are labeled with attributes:
  - `security.correlation_id`
  - `security.event_type`
  - `security.risk_score`
  - `security.actor_id`
- Logs and metrics are formatted for export to Prometheus and OpenTelemetry collectors.

## 5. Account Risk Scoring (0 - 100)

### 5.1 Scoring Formula & Weights
The Account Risk Score evaluates user accounts dynamically on a scale of 0 to 100 based on recent risk factors:
- **Failed Login Attempts**: +15 points per failed attempt within 15 minutes.
- **Rapid Profile Edits**: +20 points for multiple profile modifications within 5 minutes.
- **Rate Limit Triggers**: +25 points for hitting API rate limit thresholds.
- **Spam Reports**: +30 points when reported by other users for spam/abuse.
- **Bot Signals**: +35 points when bot confidence score > 60%.

### 5.2 Risk Levels
- **Normal (0 - 24)**: Low risk; standard access permitted.
- **Low (25 - 49)**: Mild anomalies; log for monitoring.
- **Medium (50 - 74)**: Elevated risk; **triggers automatic SecurityAlert**.
- **High (75 - 89)**: High risk; requires step-up authentication (MFA) or temporary rate limiting.
- **Critical (90 - 100)**: Severe threat; temporary account restriction / session revocation.

## 6. Automated Bot Detection Signals & Fraud Detection Heuristics

### 6.1 Bot Detection Signals (`BotDetectionSignal`)
Evaluates incoming HTTP metadata and traffic patterns:
- **IP Address & User-Agent**: Analyzes high request frequencies from single IP pools or generic headless browser user-agents.
- **Burst Rate**: Request velocity over a 10-second window (e.g. > 50 req/10s).
- **Endpoint Pattern**: Scans for sequential endpoint crawling on registration or public search APIs.
- **Bot Confidence Score (0-100)**: Calculated score combining velocity, header metrics, and behavioral entropy. Flagged as `IsBot = true` when score > 65.

### 6.2 Fraud Detection Heuristics (`FraudAlert`)
Multi-signal rules evaluate specific platform entities:
1. **Registration Bursts**: Multiple user accounts registered from the same IP subnetwork within 1 hour.
2. **Fake Job Postings**: Job listings featuring suspicious compensation metrics (> $500k entry level), repetitive phishing text, or unverified external link patterns.
3. **Mass Application Submissions**: Automated bot accounts submitting > 50 job applications per minute.
4. **Mass Messaging Spam**: Sending identical outbound messages to un-connected accounts at high frequency.

## 7. Security Rules Engine

Configurable rules govern real-time traffic filtering and security actions:

| Rule ID | Name | Category | Threshold | Window (s) | Action |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `login_failure_threshold` | Failed Login Limit | `authentication` | 5 | 300 | `temporary_restrict` |
| `message_rate_limit` | Messaging Spam Guard | `communication` | 30 | 60 | `rate_limit` |
| `connection_rate_limit` | Connection Request Guard | `social` | 20 | 60 | `rate_limit` |
| `registration_rate_limit` | IP Registration Burst Shield | `abuse` | 10 | 3600 | `block` |
| `export_rate_limit` | Data Export Rate Control | `data_privacy` | 3 | 86400 | `require_mfa` |

### Rule Actions
- `log`: Record event silently for analytical monitoring.
- `rate_limit`: Throttles HTTP requests with HTTP 429 status.
- `require_mfa`: Demands step-up TOTP verification for protected action.
- `temporary_restrict`: Temporarily locks account capability for 15-60 minutes.
- `block`: Denies request completely with HTTP 403 status.

## 8. Alert Lifecycle States

Security alerts (`SecurityAlert`) progress through defined state transitions managed by Security Operations Center (SOC) admins:

```
[ New ] ---> [ Investigating ] ---> [ Mitigated ] ---> [ Resolved ]
   |                  |
   v                  v
[ False Positive ]  [ Escalated ]
```

- **New**: Freshly generated alert awaiting SOC review.
- **Investigating**: Admin assigned (`AssignedAdminID`); triage in progress.
- **Mitigated**: Active threat risk suppressed (e.g. session revoked or IP throttled).
- **Resolved**: Investigation completed and resolution notes documented.
- **False Positive**: Identified as benign traffic; closed cleanly without penalty to account score.
- **Escalated**: Higher severity incident raised for platform engineering or legal review.

---

## 9. Session & Device Security Controls
- **Active Sessions**: Tracks session ID, client IP, User-Agent, location, and expiration. Includes self-revocation and "Revoke All Other Sessions" capability with IDOR ownership validation.
- **Trusted Devices**: Hardware/Browser fingerprint registration with status (`trusted`, `pending`, `revoked`).
- **MFA Enforcement**: TOTP (RFC 6238) integration with 8 single-use SHA-256 hashed recovery codes.

## 10. OpenAPI Specifications Summary
All endpoints are exposed under `/api/v1/security/...` (User context) and `/api/v1/admin/security/...` (Admin SOC context).
- `GET /api/v1/security`: User security overview.
- `GET /api/v1/security/risk-score`: Active account risk score details.
- `DELETE /api/v1/security/sessions/:id`: Revoke session.
- `GET /api/v1/security/login-history`: User login history.
- `GET /api/v1/admin/security/alerts`: List SOC security alerts.
- `GET /api/v1/admin/security/alerts/:id`: Alert details.
- `PUT /api/v1/admin/security/alerts/:id`: Update alert status.
- `POST /api/v1/admin/security/alerts/:id/resolve`: Resolve alert.
- `GET /api/v1/admin/security/rules`: List security rules engine configs.
- `PUT /api/v1/admin/security/rules/:id`: Update rule config.
- `GET /api/v1/admin/security/bot-signals`: List bot detection signals.
- `GET /api/v1/admin/security/fraud-alerts`: List fraud alerts.
- `GET /api/v1/admin/security/risk-scores`: List account risk scores.
- `GET /api/v1/admin/security/metrics`: Security dashboard summary metrics.
